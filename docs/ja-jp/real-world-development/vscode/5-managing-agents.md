Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューして個々の変更を採用または取り消し、エディターを離れずに追加プロンプトで作業を調整できます。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして採用する。
- セッション中にエージェントへ指示し、ハイコントラストに加えてライトモードも追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから、既定のテーマが暗すぎると感じる利用者向けにライトモードも追加してほしいという依頼がありました。新しい会話を始めるのではなく、既存のセッションに追加の指示を出します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドなどが表示されます。
3. エージェントがファイル編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開き、このセッションで変更されたすべてのファイルを確認します。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは作業を一時停止し **Allow** を表示します。許可するコマンドのみ承認してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に変更の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードの後も同じ会話を使うため、エージェントは以前の作業、変更したコンポーネント、スタイル、local storage のパターンを引き継ぎます。続けてライトモードの切り替えを依頼します。

1. Copilot Chat の入力欄に次のプロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが変更内容を調べ、ライトモードの追加を提案する様子を確認します。
3. ハイコントラストモードの場合と同様に、変更が追加されるたびにレビューし、各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図と異なる変更を提案した場合 (たとえば、気に入らない方法でトグルのユーザーインターフェイス (UI) をリファクタリングする場合) は、チャット入力欄の横にある **Stop** で停止し、追加のメッセージで意図を伝えます。

> [!TIP]
> セッション途中で指示を追加すると、最初からやり直すより早く修正できます。たとえば、「カスケーディングスタイルシート (CSS) を簡潔にして、セレクターの重複ではなく CSS 変数を使う」「3つ目のトグルを追加せず、既存の設定パネルにライトモードを追加する」「両方のトグルにキーボードショートカットも追加する」などと依頼できます。

## 変更内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれるはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など、カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、各ファイルの編集をレビューし、採用または取り消し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- 追加プロンプトでセッション中の作業を調整する。
